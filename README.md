# Универсальный Telegram-бот расписания

Самостоятельно развёртываемый Telegram-бот для публикации учебного расписания. Он загружает PDF с публичного Яндекс.Диска, накладывает ежедневные замены из DOCX и хранит выбранную группу или преподавателя отдельно для каждого чата или темы Telegram.

## Возможности

- выбор курса и группы через inline-кнопки или поиск преподавателя по фамилии;
- отдельные настройки для личных чатов, групп и тем Telegram;
- команды для просмотра расписания на сегодня, завтра, выбранную дату и неделю;
- автоматическая публикация расписания с учётом замен;
- инкрементальное обновление PDF-кэша без повторного разбора неизменившихся файлов;
- защита от дублей, ограничение частоты запросов к Telegram и изоляция ошибок отдельных чатов;
- хранение настроек и истории автоотправки в SQLite.

## Структура проекта

- `app/bot.py` — запуск, фоновые задачи и жизненный цикл;
- `app/telegram_handlers.py` — команды, кнопки и настройки чатов;
- `app/autopost.py` — автоотправка по всем привязкам;
- `app/telegram_queue.py` — единая очередь отправки и ограничение частоты Telegram API;
- `app/schedule_service.py` — выбор PDF, инкрементальный кэш и базовое расписание;
- `app/replacement_service.py` — безопасный разбор DOCX и наложение замен;
- `app/teacher_schedule.py` — расписание преподавателя по всем группам и его изменения;
- `app/schedule_formatter.py` — HTML-представление расписания;
- `app/pdf_parser.py` — разбор таблиц PDF;
- `app/storage.py` — SQLite и JSON-кэш;
- `app/telegram_api.py`, `app/yandex_disk.py` — сетевые клиенты.

## Как устроено обновление

Бот не разбирает четыре тяжёлых PDF при каждом запросе. При запуске и затем раз в `SCHEDULE_REFRESH_MINUTES` он получает метаданные файлов с Яндекс.Диска:

1. Если файлы, версия парсера и схема кэша не менялись, используется готовый `data/schedule_cache.json`.
2. Если изменился один PDF, бот скачивает и перерабатывает только соответствующий курс.
3. Смена версии парсера автоматически перестраивает кэш даже при неизменных PDF.
4. Бот проверяет обновления основного расписания автоматически в фоне.
5. Нераспознанные фрагменты не удаляются: они сохраняются в кэше с предупреждением и отмечаются в выводе расписания.

## Чаты и темы

В личном чате, группе или нужной теме Telegram выполните `/setup`. Бот предложит выбрать группу или преподавателя, после чего сохранит привязку `chat_id + message_thread_id`. Группу выбирают по курсу, преподавателя — из списка с постраничными кнопками. В разных темах одного чата можно назначить разные группы и преподавателей.

Любой участник чата может выбрать группу или преподавателя и включить либо выключить автоотправку. Выбранная настройка общая для текущего чата или темы. Проверка статуса администратора не выполняется.

Команды:

- `/setup` — выбрать или сменить группу либо преподавателя в текущем чате/теме;
- `/today`, `/tomorrow` — расписание с заменами;
- `/date DD.MM.YYYY` — расписание на дату;
- `/week` — основное расписание по дням для числителя и знаменателя;
- `/autopost_on`, `/autopost_off` — включить или выключить автоотправку в текущей теме;
- `/help` — подсказка.

Для преподавателя бот собирает пары всех групп. Ежедневные замены назначают новые пары и показывают отдельно снятые или отменённые. Список выбора формируется из PDF и семи последних опубликованных DOCX; произвольные имена не принимаются.

## Обновление и защита от повторов

Основное расписание проверяется автоматически при запуске и затем по
`SCHEDULE_REFRESH_MINUTES` (по умолчанию 60 минут). Ручного обновления нет.

Команды и кнопки ограничены до трёх запросов подряд от одного пользователя;
затем разрешается один дополнительный запрос каждые две секунды. Одинаковые
команды одного пользователя в одном чате/теме в течение трёх секунд пропускаются. Пока расписание
отправляется, повторный такой же запрос в этой теме не запускается, в том числе
от другого пользователя. При заполнении очереди новые запросы пропускаются.
Ограничения хранятся в памяти и сбрасываются при перезапуске.

## Автоотправка

Для каждой привязки с `/autopost_on` бот проверяет завтра:

- пока файла замен нет — ничего не отправляет;
- после появления файла один раз отправляет итоговое расписание;
- при изменении DOCX повторно отправляет расписание только тем группам или преподавателям, чьё итоговое расписание действительно изменилось.

Дубли предотвращаются таблицей `sent_autoposts` в SQLite. Один экземпляр бота может обслуживать множество чатов и тем.

Все исходящие сообщения проходят через одну очередь. Обычные команды имеют приоритет перед массовой автоотправкой, сообщения сохраняют порядок, а частота запросов ограничена настройкой `TELEGRAM_MESSAGES_PER_SECOND`. Это снижает вероятность Telegram `429 Too Many Requests` при большом количестве чатов.

Ошибка одной темы не останавливает остальные отправки. После трёх ошибок постоянной недоступности чата или темы (например, бот заблокирован или тема удалена) проблемная подписка автоматически отключается. Временные сетевые сбои, ограничения частоты Telegram и ошибки исходных данных не отключают подписку: бот попробует снова при следующей проверке. История отправок старше 60 дней удаляется.

Очередь выполняет до четырёх сетевых отправок параллельно в разные чаты. Порядок сообщений внутри одного чата сохраняется; ожидание лимита одного чата не задерживает готовые сообщения остальных. При ответе Telegram с `retry_after` очередь выдерживает полный указанный срок и делает до трёх попыток. Сетевые тайм-ауты автоматически не повторяются в очереди, поскольку Telegram мог уже принять сообщение.

Если DOCX содержит разные записи для одной группы и номера пары, бот сообщает о конфликте вместо выбора последней строки. Исходные строки сохраняются для проверки; автоотправка такой привязки остаётся включённой и возобновится после исправления файла. Одинаковые дубли применяются один раз.

Расписание преподавателя и недельный вывод рассчитываются по одному снимку кэша, поэтому фоновое обновление не смешивает разные версии расписания в одном ответе.

## Локальный запуск

### Windows PowerShell

```powershell
cd schedule-bot-universal
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
# заполните TELEGRAM_BOT_TOKEN в .env
python main.py
```

Настоящий токен должен храниться только в `.env`. Файл уже исключён из Git; не добавляйте токен в `.env.example`, исходный код или сообщения об ошибках.

Критичная настройка — `NUMERATOR_WEEK_START`: это понедельник недели-числителя. При публикации расписания нового семестра дату нужно обновить, иначе бот может выбрать противоположную половину ячейки.

Значение обязательно, должно быть понедельником и обязано соответствовать семестру в именах PDF. Если семестр сменился, бот остановит обновление и попросит исправить конфигурацию вместо показа расписания с неверной чётностью.

`BOT_WORKERS` задаёт число фоновых обработчиков. По умолчанию используются четыре: Telegram polling продолжает работать во время загрузки PDF, запросов замен и автоотправки.

Журнал одновременно выводится в консоль и записывается в `data/logs/bot.log`. Файл автоматически ротируется: до 5 МБ и три архивные копии. Уровень задаётся через `LOG_LEVEL`. Строки, похожие на токен Telegram, маскируются перед записью.

Параметры очереди:

```env
TELEGRAM_MESSAGES_PER_SECOND=20
TELEGRAM_QUEUE_SIZE=1000
LOG_LEVEL=INFO
```

## Безопасность

- callback-данные повторно проверяются перед изменением привязки;
- сетевые клиенты принимают только HTTPS и ограничивают размер ответа;
- скачанный файл расписания проверяется на PDF-сигнатуру;
- DOCX имеет ограничения на размер архива и XML, опасные XML-сущности запрещены;
- пользователь не получает внутренние трассировки ошибок — они остаются в журнале;
- `pdfplumber` закреплён на версии с исправленным `pdfminer.six`.

Максимальный размер одного скачиваемого PDF/DOCX — 50 МБ. Для `word/document.xml` установлен отдельный предел 20 МБ, а для распакованного DOCX — 100 МБ.

Обычные тесты:



## Развёртывание на Ubuntu 24.04

Установочный скрипт сам скачивает или обновляет проект с GitHub, устанавливает зависимости и создаёт службу `systemd`:

```bash
wget https://raw.githubusercontent.com/ZentifyID/schedule-bot-universal/main/install-ubuntu.sh
chmod +x install-ubuntu.sh
sudo ./install-ubuntu.sh
```

При первой установке он запросит токен Telegram и понедельник недели-числителя. Проект размещается в `/opt/schedule-bot-universal/repo`, а конфигурация и данные хранятся отдельно. Повторный запуск обновляет Git-репозиторий и зависимости, не удаляя `.env`, базу и кэш.

```bash
sudo systemctl status schedule-bot
sudo journalctl -u schedule-bot -f
sudo systemctl restart schedule-bot
```

Для VPS с одним ядром укажите `BOT_WORKERS=2`. При 1 ГБ памяти и совместном размещении с другими сервисами рекомендуется иметь swap. Боту не нужен входящий порт: он обращается к Telegram и Яндекс.Диску исходящими HTTPS-запросами.
