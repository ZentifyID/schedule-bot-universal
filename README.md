# Универсальный Telegram-бот расписания

Самостоятельно развёртываемый Telegram-бот для публикации учебного расписания. Он загружает PDF с публичного Яндекс.Диска, накладывает ежедневные замены из DOCX и хранит выбранную группу или преподавателя отдельно для каждого чата или темы Telegram.

## Возможности

- выбор курса и группы через inline-кнопки или преподавателя из списка;
- отдельные настройки для личных чатов, групп и тем Telegram;
- команды для просмотра расписания на сегодня, завтра, выбранную дату и неделю;
- автоматическая публикация расписания с учётом замен;
- инкрементальное обновление PDF-кэша без повторного разбора неизменившихся файлов;
- защита от дублей, ограничение частоты запросов к Telegram и изоляция ошибок отдельных чатов;
- хранение настроек и истории автоотправки в SQLite.

## Как устроено обновление

Получение команд использует long polling Telegram с ожиданием 10 секунд и
сетевым таймаутом 20 секунд. При обрыве соединения повтор начинается через
1 секунду; при последовательных сбоях пауза растёт до 5 секунд и сбрасывается
после успешного запроса. Проверки обновлений расписания и автоотправки
продолжаются даже при ошибках получения команд. Эти настройки ускоряют
восстановление после сетевого сбоя, но не устраняют проблемы маршрута до Telegram.

Бот не разбирает четыре тяжёлых PDF при каждом запросе. При запуске и затем раз в `SCHEDULE_REFRESH_MINUTES` он получает метаданные файлов с Яндекс.Диска:

1. Если файлы, версия парсера и схема кэша не менялись, используется готовый `data/schedule_cache.json`.
2. Если изменился один PDF, бот скачивает и перерабатывает только соответствующий курс.
3. Смена версии парсера автоматически перестраивает кэш даже при неизменных PDF.
4. Бот проверяет обновления основного расписания автоматически в фоне.
5. Нераспознанные фрагменты не удаляются: они сохраняются в кэше с предупреждением и отмечаются в выводе расписания.

## Чаты и темы

В личном чате, группе или нужной теме Telegram выполните `/setup`. Бот предложит выбрать группу или преподавателя, после чего сохранит привязку `chat_id + message_thread_id`. Группу выбирают по курсу, преподавателя — из списка с постраничными кнопками. В разных темах одного чата можно назначить разные группы и преподавателей.

Любой участник чата может выбрать группу или преподавателя и включить либо выключить автоотправку. Выбранная настройка общая для текущего чата или темы. Проверка статуса администратора не выполняется.

В личных сообщениях выбор группы/преподавателя и автоотправка принадлежат только
этому пользователю: его личный `chat_id` не пересекается с привязками остальных
пользователей, групп и тем. Формат календаря хранится отдельно по Telegram ID
пользователя и применяется ко всем его личным календарным ссылкам. Изменение настроек
группового чата не меняет выбор в личных сообщениях и уже выданные календарные ссылки.

Команды:

- `/setup` — выбрать или сменить группу либо преподавателя в текущем чате/теме;
- `/today`, `/tomorrow` — расписание с заменами;
- `/date DD.MM.YYYY` — расписание на дату;
- `/week` — основное расписание по дням для числителя и знаменателя;
- `/autopost_on`, `/autopost_off` — включить или выключить автоотправку в текущей теме;
- `/help` — подсказка.
- `/calendar` — личная ссылка подписного календаря выбранной группы или преподавателя;
- `/calendar_format short` — только фамилия, без описания события, только для вас;
- `/calendar_format full` — вернуть длинные заголовки (по умолчанию);
- `/calendar_off` — отозвать ваши календарные ссылки текущего чата/темы.

Для преподавателя бот собирает пары всех групп. Ежедневные замены назначают новые пары и показывают отдельно снятые или отменённые. Список выбора формируется из PDF и семи последних опубликованных DOCX; произвольные имена не принимаются.

## Обновление и защита от повторов

Основное расписание проверяется автоматически при запуске и затем по
`SCHEDULE_REFRESH_MINUTES` (по умолчанию 60 минут). Ручного обновления нет.

Команды и кнопки ограничены до трёх запросов подряд от одного пользователя;
затем разрешается один дополнительный запрос каждые две секунды. Одинаковые
команды одного пользователя в одном чате/теме в течение трёх секунд пропускаются. Пока расписание
отправляется, повторный такой же запрос в этой теме не запускается, в том числе
от другого пользователя. При заполнении очереди новые запросы пропускаются.
Ограничения хранятся в памяти и сбрасываются при перезапуске.

## Автоотправка

Для каждой привязки с `/autopost_on` бот проверяет завтра:

- пока файла замен нет — ничего не отправляет;
- после появления файла один раз отправляет итоговое расписание;
- при изменении DOCX повторно отправляет расписание только тем группам или преподавателям, чьё итоговое расписание действительно изменилось.

Дубли предотвращаются таблицей `sent_autoposts` в SQLite. Один экземпляр бота может обслуживать множество чатов и тем.

В одной проверке расчёт выполняется по общему снимку расписания. Сообщение для
одной группы или преподавателя рассчитывается один раз, даже если его получают
несколько чатов. История доставки и ошибки проверяются отдельно для каждого
получателя. Неизменившиеся успешные привязки не перезаписываются в БД.

Все исходящие сообщения проходят через одну очередь. Обычные команды имеют приоритет перед массовой автоотправкой, сообщения сохраняют порядок, а частота запросов ограничена настройкой `TELEGRAM_MESSAGES_PER_SECOND`. Это снижает вероятность Telegram `429 Too Many Requests` при большом количестве чатов.

Ошибка одной темы не останавливает остальные отправки. После трёх ошибок постоянной недоступности чата или темы (например, бот заблокирован или тема удалена) проблемная подписка автоматически отключается. Временные сетевые сбои, ограничения частоты Telegram и ошибки исходных данных не отключают подписку: бот попробует снова при следующей проверке. История отправок старше 60 дней удаляется.

Очередь выполняет до четырёх сетевых отправок параллельно в разные чаты. Порядок сообщений внутри одного чата сохраняется; ожидание лимита одного чата не задерживает готовые сообщения остальных. При ответе Telegram с `retry_after` очередь выдерживает полный указанный срок и делает до трёх попыток. Сетевые тайм-ауты автоматически не повторяются в очереди, поскольку Telegram мог уже принять сообщение.

Если DOCX содержит разные записи для одной группы и номера пары, бот сообщает о конфликте вместо выбора последней строки. Исходные строки сохраняются для проверки; автоотправка такой привязки остаётся включённой и возобновится после исправления файла. Одинаковые дубли применяются один раз.

Расписание преподавателя и недельный вывод рассчитываются по одному снимку кэша, поэтому фоновое обновление не смешивает разные версии расписания в одном ответе.

## Подписка на календарь телефона (.ics)

Календарь работает отдельно от Telegram-автоотправки и не зависит от `/autopost_on`.
Расписание **на следующий день публикуется после обнаружения файла замен**,
как при автоотправке сообщений, без ожидания 22:00. Источник проверяется каждые
`REPLACEMENT_CHECK_MINUTES` минут (по умолчанию 10); новые выбранные календари
проверяются каждые 30 секунд. Даже если в найденном файле нет замен для выбранной
группы или преподавателя, публикуется её/его основное расписание. Если файла нет,
новая дата не публикуется; воскресенье пропускается.

Изменение файла замен обновляет календарь **только при изменении итоговых событий
выбранной группы или преподавателя**. Изменения другой группы не меняют содержимое,
версии, время изменения и ETag вашей подписки. Повторная проверка источника остаётся,
но одинаковое расписание не перезаписывается в SQLite. Изменённые пары сохраняют UID,
отменённые получают `STATUS:CANCELLED`. Сбой загрузки или конфликт замен сохраняет
последнюю успешную публикацию. После запуска бот также догружает текущий день при
наличии его файла замен. В подписке сохраняются события за последние 30 дней, сегодня
и завтра по `BOT_TIMEZONE` (по умолчанию `Europe/Saratov`). Более дальние даты не публикуются.

Сначала выберите группу или преподавателя через `/setup`, затем выполните `/calendar`.
В календарь группы попадают только её пары; в календарь преподавателя — только
его активные пары из всех групп, с учётом замен. Каждая ссылка **закреплена за конкретным
выбором**. Смена `/setup` не меняет старую подписку: выполните `/calendar` снова и
удалите старую подписку на телефоне, если она больше не нужна. Повторный `/calendar`
от того же пользователя для того же чата/темы и выбора возвращает ту же ссылку.
У разных пользователей ссылки разные, даже в общем чате. `/calendar_off` отзывает
только ваши личные ссылки этого чата/темы; уже скачанные события могут остаться на
телефоне до удаления подписки.

Длинные заголовки включены по умолчанию. `/calendar_format short` меняет их на
фамилию: например, «Зыбина», «Плохотнюк», «Семин». Кабинет или другое место занятия
остаётся в поле места проведения (`LOCATION`, «Геопозиция» на iPhone). В обоих
форматах обозначения места приводятся к виду «506б каб.», «112 каб.»,
«кор. 4 этаж», «ков. 2 этаж», «спортзал».
В коротком режиме описание (`DESCRIPTION`, «Сведения») не передаётся. Для календаря преподавателя
указывается его фамилия; для пары с несколькими преподавателями — фамилии через `/`.
Если преподаватель неизвестен, используется «Пара». `/calendar_format full` возвращает
длинный вариант с описанием. Настройка сохраняется для пользователя и действует на
все его личные ссылки, включая созданные позднее. Ссылка и UID событий при смене формата сохраняются,
переподключать личную подписку не нужно.
После обновления бота версии событий уже существующих коротких подписок повышаются
один раз, чтобы календарные приложения получили новый формат при обновлении.
Изменение обозначений места также один раз повышает версии сохранённых событий
во всех форматах, включая старые общие ссылки.

Старые общие ссылки, созданные до персональных настроек, продолжают работать с
длинными заголовками. Для индивидуального формата один раз получите новую ссылку
через `/calendar`, подключите её и удалите прежнюю подписку на телефоне.

- **iPhone (iOS 26):** Календарь → Календари → Добавить календарь → Добавить подписной календарь.
  Вставьте HTTPS-ссылку из бота и подтвердите подписку. На более старых iOS подписку
  можно добавить через настройки аккаунтов Календаря → Другой → Подписной календарь.
- **Google Calendar:** в веб-версии на компьютере Другие календари → `+` → Добавить по URL.
  Вставьте ту же HTTPS-ссылку, затем включите отображение календаря в приложении телефона.

Нужна именно **подписка по URL**, а не разовый импорт `.ics`. Календарные приложения
сами выбирают частоту обновления: публикация на сервере не гарантирует
появление событий на телефоне в ту же минуту или к началу занятий. Это особенно
важно при проверке Google Calendar. UID и версии событий сохраняются в SQLite,
поэтому повторные проверки и перезапуск не создают новые события для тех же пар.

### Настройка HTTPS на сервере

Без `CALENDAR_PUBLIC_URL` функция отключена: бот продолжает обычную работу и не
открывает HTTP-порт. Для включения нужен домен с DNS-записью на VPS и действующий
TLS-сертификат. В серверном `.env` (при установке скриптом — `/opt/schedule-bot-universal/.env`):

```env
CALENDAR_PUBLIC_URL=https://schedule.example.org
CALENDAR_PORT=8765
BOT_TIMEZONE=Europe/Saratov
```

Замените домен своим. `CALENDAR_PUBLIC_URL` должен содержать только HTTPS-адрес
сервера без пути, параметров и логина. Старый параметр `CALENDAR_PUBLISH_TIME`
больше не используется и может быть удалён из `.env`. После изменения `.env`
перезапустите службу.

Бот слушает только `127.0.0.1:8765` и отдаёт только `/calendar/<случайный-токен>.ics`.
Откройте наружу HTTPS через существующий обратный прокси. Пример блока для **уже
настроенного HTTPS server в Nginx** (внутри `server`, где настроены домен и сертификат):

```nginx
location /calendar/ {
    access_log off;
    error_log /dev/null crit;
    proxy_pass http://127.0.0.1:8765;
    proxy_connect_timeout 5s;
    proxy_read_timeout 10s;
    proxy_buffering on;
    proxy_cache off;
    proxy_hide_header Server;
    proxy_set_header Host $host;
}
```

Проверьте конфигурацию `sudo nginx -t`, затем выполните `sudo systemctl reload nginx`
и `sudo systemctl restart schedule-bot`. Для Caddy эквивалент при свободных 80/443:

```caddy
schedule.example.org {
    handle /calendar/* {
        reverse_proxy 127.0.0.1:8765
    }
    respond 404
}
```

Не открывайте порт 8765 в интернет. Ссылка содержит секрет доступа к выбранному
расписанию, без Telegram ID и без списка остальных подписок; передавший ссылку
передаёт доступ. Не включайте журналы URL этого маршрута в прокси. Установочный
скрипт бота не устанавливает и не меняет прокси, DNS и сертификаты автоматически.

После настройки запросите `/calendar`, проверьте адрес в браузере: ответ должен
быть `text/calendar` и начинаться с `BEGIN:VCALENDAR`. До фоновой публикации ответ
может содержать пустой календарь. Затем подключите подписку на телефоне и проверьте
пары на завтра после появления файла замен, время пар, оба формата заголовков,
изменения и отсутствие лишних групп.

## Локальный запуск

### Windows PowerShell

```powershell
cd schedule-bot-universal
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
# заполните TELEGRAM_BOT_TOKEN в .env
python main.py
```

Настоящий токен должен храниться только в `.env`. Файл уже исключён из Git; не добавляйте токен в `.env.example`, исходный код или сообщения об ошибках.

Критичная настройка — `NUMERATOR_WEEK_START`: это понедельник недели-числителя. При публикации расписания нового семестра дату нужно обновить, иначе бот может выбрать противоположную половину ячейки.

Значение обязательно, должно быть понедельником и обязано соответствовать семестру в именах PDF. Если семестр сменился, бот остановит обновление и попросит исправить конфигурацию вместо показа расписания с неверной чётностью.

`BOT_WORKERS` задаёт число фоновых обработчиков. По умолчанию используются четыре: Telegram polling продолжает работать во время загрузки PDF, запросов замен и автоотправки.

Журнал одновременно выводится в консоль и записывается в `data/logs/bot.log`. Файл автоматически ротируется: до 5 МБ и три архивные копии. Уровень задаётся через `LOG_LEVEL`. Строки, похожие на токен Telegram, маскируются перед записью.

Параметры очереди:

```env
TELEGRAM_MESSAGES_PER_SECOND=20
TELEGRAM_QUEUE_SIZE=1000
LOG_LEVEL=INFO
```

## Безопасность

- callback-данные повторно проверяются перед изменением привязки;
- сетевые клиенты принимают только HTTPS и ограничивают размер ответа;
- скачанный файл расписания проверяется на PDF-сигнатуру;
- DOCX имеет ограничения на размер архива и XML, опасные XML-сущности запрещены;
- пользователь не получает внутренние трассировки ошибок — они остаются в журнале;
- `pdfplumber` закреплён на версии с исправленным `pdfminer.six`.

Максимальный размер одного скачиваемого PDF/DOCX — 50 МБ. Для `word/document.xml` установлен отдельный предел 20 МБ, а для распакованного DOCX — 100 МБ.

## Локальные проверки

Используйте Python 3.12, как в GitHub Actions, и зависимости из `requirements-dev.txt`.

Обычные тесты:

```powershell
python -m unittest discover -s tests -v
```

Проверка на четырёх реальных PDF:

```powershell
$env:SCHEDULE_PDF_DIR='C:\путь\к\папке\с\pdf'
python -m unittest tests.test_core.RealPdfTests -v
```

Проверка зависимостей на известные уязвимости:

```powershell
python -m pip install -r requirements-dev.txt
python -m pip_audit -r requirements.txt
```

Статический security-анализ:

```powershell
python -m bandit -r app
```

После публикации репозитория GitHub Actions выполняет unit-тесты, Ruff, Bandit и `pip-audit` при каждом push и pull request. Dependabot раз в неделю проверяет Python-зависимости и версии GitHub Actions.

## Развёртывание на Ubuntu 24.04

Установочный скрипт сам скачивает или обновляет проект с GitHub, устанавливает зависимости и создаёт службу `systemd`:

```bash
wget https://raw.githubusercontent.com/xaku56/schedule-bot-universal/main/install-ubuntu.sh
chmod +x install-ubuntu.sh
sudo ./install-ubuntu.sh
```

При первой установке он запросит токен Telegram и понедельник недели-числителя. Проект размещается в `/opt/schedule-bot-universal/repo`, а конфигурация и данные хранятся отдельно. Повторный запуск обновляет Git-репозиторий и зависимости, не удаляя `.env`, базу и кэш.

```bash
sudo systemctl status schedule-bot
sudo journalctl -u schedule-bot -f
sudo systemctl restart schedule-bot
```

Для VPS с одним ядром укажите `BOT_WORKERS=2`. При 1 ГБ памяти и совместном размещении с другими сервисами рекомендуется иметь swap. Без календарных подписок боту не нужен входящий порт: он обращается к Telegram и Яндекс.Диску исходящими HTTPS-запросами. Для `.ics` нужен публичный HTTPS через обратный прокси, как описано выше.

## Сохранение данных и совместимость

Команды Telegram, URL календарей, UID событий и форматы существующих данных
сохраняются. Старые схемы SQLite мигрируют в одной транзакции; неудачная миграция
откатывается. Новый PDF заменяет локальный исходник только после успешного разбора.
Ошибка записи JSON-кэша сохраняет прежний файл и удаляет временный. Ошибка запуска
или остановки календаря не оставляет открытой очередь отправок бота.

Сложность PDF/DOCX-парсеров, очереди отправки и обработки отменённых событий ICS
сохранена: эти участки отвечают за особенности таблиц, лимиты Telegram и корректное
обновление подписок. Отдельные слои моделей, интерфейсов и менеджеров для них не нужны.
